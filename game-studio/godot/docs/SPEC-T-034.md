## Goal
Make the data core playable: each workday the player finds today's data files, opens them in a spreadsheet-like **Sheet** app, cleans them with an editable step list, builds charts, arranges a small dashboard, and attaches charts/tables and findings to the Mail report. Mouse-first, editable until Send, readable at 640x360.

## Guard rules
Same failing test after 2 fix attempts: stop and report root cause. Spec conflict: stop and report; do not lower targets silently. About 150 minutes; milestone commits (wiring, Sheet, Charts, Dashboard, Report, tests). Godot commands with timeout <= 5 min; strictly one Godot process at a time. No network/push/merge. Handoff in `game-studio/godot/docs/HANDOFF-T-034.md` with real counts (no placeholders).

## Build
1. **Wiring**: `DataGame` (T-033 facade) is created with the world in `game_flow`/desktop, one per run (seeded). New desktop icons: **Files** (Inbox: today's files with name, row count, a "new" badge, dirt hint level by difficulty only as a plain "looks messy?" nothing else), **Sheet** (opens the selected file), **Charts**, and the existing **Insight BI** becomes the **Dashboard**. Opening a file costs clock minutes via a new minimal world method (add `WorldGame.spend_minutes(n)` or reuse the existing clock path; config key `data.minutes_per_file` and `data.minutes_per_chart` in `data/datasets.json`), never Energy (balance is T-036's job). The T-023 deadline bands still apply.
2. **Sheet app**: scrollable table (virtualized rows for 400-row files), column headers with type icons and a column menu (sort, filter, standardize, convert, fill/drop missing, parse date, computed column), a top toolbar for the 13 operations (see `ops.gd`) using simple dialogs with dropdowns and number steppers (no typing required except values; allow keyboard where easy), **row-count before/after preview** per step, the **step list** panel (edit, reorder up/down, delete, undo/redo, reset to raw), error display for failed steps, highlight of rows changed/removed by the last step, summary stats strip (count, mean, median, min, max, nulls) for the selected column, and a "Looks fine?" checklist helper that lists nothing hidden (no defect hints beyond what a human could see). Keep text readable (font size >= 8 logical px, row height >= 12, hit targets >= 14x14). Provide a zoom toggle (1x/2x) for the grid.
3. **Chart builder**: pick the table (raw or the pipeline's current result), chart type (bar, line, scatter, histogram, pie), x, y, aggregation, series, axis min/max, sort, title and unit label; live preview rendered in code with palette v4 (axes, ticks, labels, legend, gridlines); the **quality flags** from `check_chart` appear as friendly warnings with teaching text (keys `chart_flag_<id>`, `chart_teach_<id>`: you fill English strings in `strings_v2.json` under a `data_ui` section). "Pin chart" saves chart spec + pipeline steps as a report attachment (max 3 attachments total with news evidence, or 4 including news; decide and document).
4. **Dashboard** (Insight BI app): a 2x2 grid where the player places up to 4 pinned charts/KPI tiles; KPI tile = a cleaned aggregate (e.g. 7-day average). Layout editable until Send.
5. **Mail report**: new section "Analysis": attached charts/tables (thumbnails + titles, remove button) and a **findings picker**: statements generated by the engine as options (`DataGame` provides them: correct and distractor variants, from the T-033 findings API), the player selects those they believe; free of hidden truth. `submit_report` payload gains an optional `analysis` dictionary (attachments + chosen findings + pipeline steps); when absent behavior is unchanged. After the review, the existing grader results appear in the review meeting as a new step "Your analysis": defects fixed/missed/wrongly fixed (from `review(day)`), findings right/wrong, chart quality flags, and the reference steps in plain words (use Handbook/coaching content ids from `data/cases.json`, `data/handbook.json`, `data/coaching.json` if the day's file type maps to a case; code the mapping minimally and document; full learning layer is T-035).
6. **Scoring hook (small and safe)**: a good analysis adds a bonus to the existing report grade (config `data.analysis_bonus`, default small); a missing analysis changes nothing; a confidently wrong analysis may reduce trust slightly (config, default 0 for now so `balance_world` stays identical; T-036 will tune). With `analysis` absent, all existing tests and `balance_*` outputs stay identical.
7. **Tutorial**: extend the day-1 coach marks with 3 steps for Files/Sheet/Chart using the day-1 tutorial case from `docs/TUTORIAL-CASES.md` (duplicates and spelling variants), skippable; Help replays.
