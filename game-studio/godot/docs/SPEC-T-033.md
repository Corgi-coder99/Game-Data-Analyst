## Build (all under `scripts/data/`, data under `data/datasets.json`)
1. `dataset.gd`: typed table (columns with type text/int/float/date/bool/category, rows), cell access, copy, row count, simple CSV-like text export/import for tests, deterministic ordering.
2. `generator.gd`: given `WorldGame`/scenario trajectory (read the hidden states via the scenario only inside the generator), the day, and an own RNG stream (seeded from the world seed and day; must not consume the world/life RNGs), produce 1 to 3 files per day (types in design section 2; at least `sales_export`, `market_prices`, `web_funnel`, `loan_book`, `ab_test_log`, `support_tickets`, `competitor_scrape`), each 40 to 400 rows, values derived from the hidden variables' direction/magnitude over the previous days and the active shock, plus noise. Mapping of variable to dataset and noise levels live in `data/datasets.json`.
3. **Dirt injection** (design section 3): implement at least 12 defect types (duplicates, missing in 3 encodings, mixed units, mixed date formats, category typos/casing, entry-error outliers, repeated headers, subtotal rows, refunds negatives, test accounts, late-arriving partial last day, join-key mismatch). Each file gets a **dirt manifest** (type, columns, rows affected) kept hidden behind an API that only works after the day's review. Difficulty parameter by day (ramp from 1 dirt type, small file, on day 1 to 4-6 types on later days) in config.
4. `ops.gd` + `pipeline.gd`: the no-code operations from design section 4 (sort, filter, dedupe, handle missing, standardize text, convert unit/currency, parse date, computed column, group-by/aggregate, pivot, lookup/join, outlier flag/remove by IQR or z, sample), each as a pure function on datasets with a serializable step dictionary; a pipeline holds an ordered list of steps, recomputes from raw, supports insert/edit/reorder/delete, undo via step list, row-count preview per step, error results (never crash) for invalid steps. Deterministic.
5. `charts.gd`: chart spec dictionary (type bar/line/scatter/histogram/pie, x, y, aggregation, series, axis min/max, sort) plus data extraction (series points) and a **quality checker** returning flags: truncated bar axis, dual axis, too many categories, unsorted bars, missing units, smoothing hiding spikes, pie with too many slices, with ids and teaching text keys.
6. `reference.gd` (hidden): for each generated file, the reference pipeline that cleans it and the **truth statements** computed from the cleaned data and the hidden state (e.g. metric direction/percentage band over 7 days, which spike is a data error, whether the A/B result is significant). `grader.gd`: scores a submitted pipeline result and chart/findings against the reference: cleaning correctness (defects fixed, missed, wrongly "fixed"), findings accuracy, chart quality. APIs are leak-safe: public API returns only dirty files before review; `review(day)` returns manifest, reference result and truth.
7. Public facade `scripts/data/data_game.gd` for the future UI: `files_today(day)`, `apply_pipeline`, `chart_data`, `check_chart`, `submit_analysis(...)`, `review(day)`. Not wired into game flow yet (T-034), but add a tiny flag-free hook is NOT needed.

## Tests (new, headless)
- Dataset/ops: each operation exact outputs on fixtures; invalid steps return errors; pipeline recompute, reorder, edit, delete; determinism by seed.
- Generator: same seed gives identical files; different days differ; row counts in range; dirt manifest matches actual defects (re-detect each injected defect by an independent checker); difficulty ramp.
- **Solvability**: for 300 seeds x all dataset types, the reference pipeline reaches the truth statements; and a naive pipeline (no cleaning) gives a worse or wrong answer in a measurable fraction (report the %), especially for outlier/unit/duplicate defects.
- **Information value**: with the reference pipeline the direction of the hidden target variable is recoverable with accuracy >= 80% over 2000 days; with no cleaning accuracy is clearly lower (report numbers); with sloppy cleaning (drop all rows with any missing) report numbers.
- Leak probe: before review, no public API output or file contains hidden-state names/values/manifest keys; extend the existing probe and source scan.
- Charts: quality checker flags each misleading case and no false flags on a good chart.
- Existing tests all pass (test_sim, test_ui, test_world, test_life, test_vitals, test_daily_flow, test_t027, test_t030_meta, test_t030_flow, test_t031_english, test_v2_*) and `balance_sim` identical; fill the handoff with real counts.
