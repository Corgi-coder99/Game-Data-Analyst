## Part A: pixel font (original design, generated by a tool script)
1. `tools/gen_font.gd` builds the font from **text-art glyph definitions in code** (like the sprite pipeline): two faces: **Body** (cap height 7 px, x-height 5, proportional widths, for sizes that replace the current 8 px text) and **Title** (bolder/taller, cap height 9-10 px, for the current 12 px headings). Glyph set: ASCII 32-126 plus every non-ASCII character currently used in `data/*.json` strings, scripts and scenes (scan them: e.g. middle dot, en/em dash, bullet, arrows, check/cross marks, multiplication sign, ellipsis, degree, percent variants); missing glyphs fall back to the default font. Output: PNG atlas(es) under `assets/v2/fonts/` (palette-free white-on-transparent, binary alpha) and a font resource Godot can load (BMFont `.fnt` text files or a `FontFile` built at load with `set_texture_image`/glyph rects; choose the more robust one and document it). Deterministic output; `tools/check_palette.gd` must treat the atlas as allowed (white + transparent) or skip the fonts folder explicitly with a documented rule.
2. Metrics rule: at each replaced size the new font's line height and average advance must be **no larger** than the default font's at that size (measure both and print a table), so existing layouts keep fitting. Legibility first: distinct `0/O`, `1/l/I`, `5/S`, clear punctuation, comfortable spacing.
3. Apply through `theme_v2.gd` (one place), integer scaling only, no filtering/antialiasing, hinting off. Add a Settings toggle **"Pixel font"** (default on; off restores the default font) stored in the profile (additive field, backward compatible).
4. Check every screen: nothing clipped or overlapping at 640x360 in both font modes for the key screens.

## Part B: juice (all skippable, all respect a new Settings toggle "Reduce motion", default off)
Add a small helper `scripts/v2/juice.gd` and use it via one-line hooks:
- Scene transitions: quick palette-friendly fade or pixel-dissolve between states (0.2-0.35 s), must be disabled when `fade_enabled` is false (tests rely on it).
- Windows and popups: open/close scale-and-fade (0.12 s), toasts slide in, dialogs ease.
- Buttons: 1 px press offset and a brief highlight; hover lift for cards and shop storefronts.
- Numbers: money and XP count up/down; `+$`/`-$` popups get a small bounce; coins sparkle (few pixels) on income; confetti burst (palette v4 colors, < 60 particles, 0.8 s) on promotion, level-up, achievement and tutorial case solved.
- Characters: screen shake (2-3 px, 0.25 s) and desk shake when Khoi slams the keyboard; small hop on happy emotes; idle blink where missing.
- Day title card at day start ("Day 3"), deadline clock pulse when the band turns yellow/red, Send button gentle pulse when the report is ready.
- Charts: bars grow in, lines draw left to right (0.3 s) on first render only.
Rules: no change to logic, timing-dependent tests keep passing (provide `Juice.enabled`/`instant` switches that tests can turn off, default behavior safe in headless), no input blocking longer than 0.35 s, Esc skips, Reduce motion turns animations into instant state changes, particles are cheap (CPU particles or manual draw), 60 fps on the windowed tests.
