# Data Corp (working title)

A single-player pixel-art office simulation about data analysis, built with Godot 4.7 (GDScript). You are a data analyst at a small company during a credit crisis. Each day you read a simulated "internet" on your office computer, verify which news is trustworthy, write a forecast report for your boss, and live with the consequences: a bonus and a promotion if you are right, a penalty or dismissal if you are wrong.

All companies, people, tickers and figures in the game are fictional. They are not real market data and not investment advice. Part of the content and code was created with AI assistance.

## Features

- Daily loop: question from the boss, news triage, verification tools with limited Energy, a written report, an end-of-day review.
- News from sources of different reliability (official, press, social media, internal tips). True, false, partly true, outdated and irrelevant items appear on every kind of source, so you must verify instead of relying on a fixed rule.
- Reports are scored on forecast accuracy, calibrated confidence and evidence quality, not on luck.
- Career ladder with boss Trust, bonuses, warnings, demotion and dismissal; the company can also go bankrupt.
- 640x360 pixel art with integer scaling. All sprites are generated by code with a locked 32-color palette (no external assets).
- Deterministic scenarios from a seed, plus a headless balance simulation.

Two versions live in this repository:

- **v2 (current):** the office and computer-screen game described above. Entry scene: `res://scenes/v2/main_v2.tscn`.
- **v1 (dashboard card game):** the earlier prototype, still the project's default scene. Its UI strings are currently in Vietnamese.

## Requirements

- [Godot 4.7](https://godotengine.org/) (standard build, no .NET needed).
- Python 3 (only for the optional web check script in `media-marketing/web/`).

## Run the game

Open the `game-studio/godot` folder in the Godot editor and run the scene `scenes/v2/main_v2.tscn`, or from a terminal:

```bash
godot --path game-studio/godot res://scenes/v2/main_v2.tscn
```

Add `-- --seed=7` to fix the scenario. On a fresh clone Godot imports the assets on first open; to do it without the editor:

```bash
godot --headless --import --path game-studio/godot
```

See `game-studio/godot/docs/PLAY-v2.md` for how to play and the controls.

## Tests

Run from the repository root (use the console build of Godot on Windows, for example `Godot_v4.7.2-stable_win64_console.exe`):

```bash
# Simulation and world logic
godot --headless --path game-studio/godot -s res://tests/test_sim.gd
godot --headless --path game-studio/godot -s res://tests/test_world.gd
# v2 game flow
godot --headless --path game-studio/godot -s res://tests/test_v2_flow.gd
# Layout and render checks (must NOT be headless; they measure real sizes)
godot --path game-studio/godot -s res://tests/test_v2_screens_render.gd
godot --path game-studio/godot -s res://tests/test_v2_layout_render.gd
# Balance simulation (headless, prints win rates per strategy)
godot --headless --path game-studio/godot -s res://tests/balance_sim.gd
```

Other tests live in `game-studio/godot/tests/` (`test_ui.gd`, `test_v2_*.gd`, `balance_world.gd`).

## Project structure

```
game-studio/godot/        Godot 4 project
  data/                   Game data as JSON (config, cards, events, news, world, strings)
  scenes/, scripts/       v1 dashboard (scripts/sim, scripts/ui) and v2 (scripts/world, scripts/v2)
  tests/                  Headless tests and balance simulations
  tools/                  Code-based sprite generator and palette checker
  assets/                 Generated sprites and UI theme
  docs/                   Design docs (GDD, content bible, play guide) and task specs
shared/style-bible/       Pixel-art style bible and machine-readable palette
media-marketing/web/      Static landing page and its check script
docs/                     Repository-level docs (collaboration, commit conventions, GitHub readiness)
```

Game data is kept separate from code: balance numbers live in `data/*.json`, and the simulation core in `scripts/sim/` has no node dependency so it can run headless.
